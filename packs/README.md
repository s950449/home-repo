# External skill packs

Each directory declares a small, opt-in selection and its native
`skills-lock.json`. All Git sources use full 40-character commit pins.
Root npm dependencies pin the installer separately from skill content.

## Declaration versus lock

- `package.json` `skills`: Native Git source declarations using immutable
  GitHub tree URLs. The current wrapper intentionally accepts only full-commit
  GitHub sources, not mutable branches, tags, or arbitrary download endpoints.
- `skills-lock.json`: Generated by `skills@1.9.0`, with the resolved `commit`,
  source path, and `computedHash` for the complete installed bundle.
- Root `package-lock.json`: Locks the CLI and npm dependencies with npm integrity
  values. It does not install the external skills by itself.
- `homeRepo.skillIds`: Maps a declared upstream directory to the native skill
  ID when the names differ. For example, Remotion uses `skills/remotion` for
  `remotion-best-practices`.

`reverse-engineering` is the sole vendored exception. `homeRepo.localSkills` is custom
Home Repo metadata pointing to a relative, Git-tracked vendored bundle.
The CLI's native `skills` field rejects local paths. The wrapper uses native
`skills add` to create/update this local lock and native frozen restore afterward.
No absolute machine path is committed.

## Ordinary restoration

Run from the repository root:

```sh
npm run skills:plan -- cloudflare-worker --agent codex
npm run skills:restore -- cloudflare-worker --agent codex
```

Accepted agents are `codex`, `opencode`, `pi`, and `claude-code`. Multiple explicit
IDs are allowed. The wrapper does not permit `--global`, arbitrary CLI options,
automatic agent detection, or implicit lock writes.

Restores use the lock's commit, validate content against its SHA-256 hash, and
fail rather than change the lock. Plans use native `--dry-run`; they do not
download or verify remote content. Both commands first validate declarations
and any existing local installations.

Native restore can overwrite modified files, so the wrapper adds a conservative
preflight: untracked destinations, modified canonical files, modified agent
copies, unsafe parent links, or links outside the pack cause it to stop.
Internal bundle symlinks are rejected rather than followed.

The CLI normally uses `.agents/skills` plus agent links. On Windows it uses
junctions and can fall back to copies. The local REA lock explicitly records
copy mode. Generated installation details are not committed. Actual Windows
and macOS behavior has not been tested here.

## Explicit maintenance

Do not use `skills update` during startup or ordinary restore.

1. Prepare a branch or separate checkout, not a pack used by a running session.
2. Review upstream changes and choose a full commit.
3. Edit the relevant `package.json` declarations.
4. Explicitly synchronize:

   ```sh
   npm run skills:sync -- cloudflare-worker --agent codex --write-lock
   ```

5. Review native lock changes. Run `npm run validate` and `npm test`, then verify
   a clean frozen restore before committing.

Sync uses native `experimental_sync` for Git declarations. This command and the
restore alias are experimental upstream features, which is why the installer is
pinned. The local exception uses native `skills add --copy` instead.

Do not hand-refresh content hashes to conceal local changes. Preserve intentional
customizations as personal skills or documented forks before restoring. The
wrapper does not offer a force-overwrite switch.

Installed pack sources remain in the pack directory. Profiles can combine
multiple restored packs with local personal skills, then explicitly deploy
independent snapshots into a selected project/worktree. See
[`profiles/README.md`](../profiles/README.md). Pack restore never deploys
implicitly. Existing global skills are neither hidden nor removed by selecting
a pack or profile.
